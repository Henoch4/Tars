## TreasuryMultisig.sol (378 lines) — FIXED today, then triaged

Pre-scan state: did not compile at all. Fixed 2026-10-09 (all verified
by recompile + rescan; 12 residual results, all below):

1. `transactions.push(Transaction({...}))` never compiled (struct holds
   a mapping) → push-empty + field assignment.
2. `nonReentrant` was `_;`-only (a guard in name that guarded nothing) →
   real OZ-style mutex.
3. `threshold`/`timelockDelay` wrongly `immutable` while rotation writes
   them → mutable with rationale (owner stays immutable).
4. `getTransaction` returned an unreturnable mapping struct → tuple of
   the 7 scalar fields.
5. Redundant `isSigner()` getter deleted (public mapping already exposes it).
6. Stale `transactionCount` (always 0) → maintained on submit.
7. `executeTransaction` sets executed-before-call (mutex + CEI).
8. `tx` locals renamed (builtin shadowing).

Then the forge suite (`contracts/contracts/TreasuryMultisig.t.sol`,
foundry 1.6.0-nightly, installed same day) was repaired alongside:
10 failing tests were ALL test bugs (bare selectors on arg-ful custom
errors, missing owner pranks, unfunded ether sends, a threshold test
missing its confirm call, an insufficient-signers test that never
triggered the guard) — zero contract bugs found by the repair pass.
Result: **18/18 green, including a genuine reentrancy attack drill**
(malicious signer-contract re-enters mid-execution; outer call fails
closed, funds stay put).

| Residual detector | Verdict | Rationale |
|---|---|---|
| `timestamp` (timelock) | **Accepted by design** | 48h+ timelocks; slack irrelevant. |
| `low-level-calls` (execute) | **Accepted by design** | A multisig must forward arbitrary calldata; mutex + threshold + timelock bound it. |
| `costly-loop`, `cache-array-length` | **Gas nits** | Bounded signer sets; documented, not fixed pre-audit. |
| Unused `returnData`/stub getters | **Known** | Contract is undeployed and OUT of audit scope (see below). |
